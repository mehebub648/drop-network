# v0.0.52 -> v0.0.53

Searching for donors and posting a blood request are now the same thing.

## There is no request form any more

Someone standing in a hospital corridor was previously asked to fill in a
fourteen-field form before finding out whether any donor was even available.

- `/request/new` is gone and redirects to `/directory`.
- Searching *is* posting. Pick blood group, district and upazila; the details you
  give to unlock a phone number become your published request.
- Nothing is pre-selected in the three search fields. A default silently searches
  the wrong place, which is worse than an empty field.
- The collection facility and "who are you?" questions appear only once the first
  three are answered, so the opening screen stays short.
- Consent to publish is still an explicit checkbox. It was never inferred from
  pressing Search.

## Numbers are masked for everyone, and open one at a time

- Search results mask every number, including for signed-in members. The old
  behaviour handed every match's full number to anyone with an account.
- A number opens through an explicit reveal that requires a verified phone, an
  active request you own, and the donor still being in that request's own
  results. That last check is what stops one published request from becoming a
  bulk lookup of the whole directory.
- **Imported listings can now be revealed too, which reverses a previous
  promise.** Those people never signed up here, so the reveal is deliberately
  narrow: their own district and upazila, one at a time, every reveal recorded,
  the call page saying plainly that they are not expecting the call, and source
  attribution on every card. There is still no way for a listed person to ask to
  be removed without claiming the profile; that is now tracked in the plan.

## Every call gets an answer

- Opening a number leads to a call page with the number in full, a copy button
  and a dial button, and the question of how the call went.
- Outcomes: the donor agreed, you didn't call, no answer, wrong number, or they
  declined - with a reason, and for "too far" a follow-up. The success option was
  not in the original design; without it an honest requester whose call went well
  had nothing truthful to click.
- The next number will not open until the last call is reported. Leaving the page
  defers the question rather than escaping it. A hard client-side lock is not
  possible, so the page does not pretend to be one.
- Nothing a requester reports changes the donor's record. "She recently donated"
  is an unverified third-party claim, and acting on it would let anyone
  deactivate any donor with a single click.

## Signing in without leaving the page

- Giving a phone number signs you in or registers you in place, so a
  half-completed request is never lost to a login redirect.
- New `SIGN_IN` verification purpose: it works whether or not the number has an
  account, and only says which after you enter the code sent to that number - so
  you learn about your own phone and nobody else's. There is deliberately no
  endpoint that answers "is this number registered?".
- A verified code can sign you in outright, so a password you set months ago is
  not a blocker in an emergency. The password path still works.

## The donor's side

- New "Requests near you" in the member area: open requests your blood group can
  answer in your upazila.
- The requester's number is masked there too, and opens when you say you can
  help - the mirror of how your own number is treated.
- Responses include "they no longer need blood", "I could not reach them", and a
  misuse report that files a moderation case.
- A donor's report about themselves *may* update their own record, because it is
  self-declared. Marking yourself unwell is an opt-in checkbox, not automatic.

## Under the hood

- Blood compatibility, districts and upazilas now have a single owner in
  `server/`, re-exported to the frontend. The comment asking someone to keep two
  copies of the compatibility table in sync is gone, and the donor feed's
  reverse direction is derived from the forward table rather than hand-typed.
- Compatible blood groups are included in results, with the patient's exact group
  ranked first and registered members above public listings.
- Added `@types/react` and `@types/react-dom`, which were missing. The codebase
  type-checks clean with them.
- The imported-donor backfill now tracks progress with a `row_version` column
  instead of testing whether a value still looks empty. A row whose upazila is
  legitimately blank would otherwise have matched its own migration predicate
  forever.
