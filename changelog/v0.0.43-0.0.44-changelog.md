# v0.0.43 → v0.0.44

**First full run:** 141,966 scraped rows → **130,218 unique donors** imported
(11,738 duplicates merged, 10 rejected). 129,467 have a phone number and
129,631 are placed by district and blood group. Seven upazila/blood-group
combinations hit the source's 500-row cap and are tracked in `docs/PLAN.md`.

## Imported donor directory

Donor listings that other Bangladesh organisations publish openly can now be
imported as **claimable profiles**.

### Scraping

- New `scripts/scrape/` with one module per listing:
  - **Bangladesh Scouts** (`bd-scouts`) — name, membership id, mobile number,
    district and upazila. The search page caps every result set at 500 rows, so
    the scraper queries each upazila crossed with each blood group and logs any
    combination that still hits the cap.
  - **Quantum Voluntary Blood Donation Program** (`quantum-method`) — names and
    donation counts only. Their API publishes no contact details and ignores
    every paging parameter, so only the ends of each rank list are readable.
- `npm run scrape` writes NDJSON per source into `data/scraped/` (git-ignored).
  `--resume` continues an interrupted run without losing what it collected.
- The fetcher backs every worker off when a host returns 429/502/503/504, with
  a doubling cooldown. The Scouts register started returning 504s at 16
  concurrent searches, so it is queried 4 at a time; a full run takes hours,
  which is the host's limit rather than something to optimise away.
- Adding a listing means adding a descriptor to `IMPORT_SOURCES` and a module
  that yields records.

### Importing

- `npm run import-donors` normalizes, dedupes and loads the NDJSON into a new
  `imported_donors` table. Unrecognised blood groups and districts are blanked
  rather than guessed, so a claimant has to fill them in.
- Records sharing a phone number collapse into one profile across sources.

### Privacy

Imported people never registered here, so their records are stubs, not accounts:

- Phone numbers are always served masked (`+88017••••••78`).
- Imported records never enter the donor match partitions and are never invited
  to a request.
- A claim is auto-approved only when the claimant's own verified phone matches
  the number the source published. Everything else waits for an operator.
- A claimed profile starts as `NOT_AVAILABLE` — being listed elsewhere is not
  consent to be contacted here.

### New surfaces

- `/directory` browses unclaimed profiles by blood group, district, source and
  name, and shows attribution back to each original listing.
- `/directory/:id` is the claim form, which requires any field the source left
  empty.
- API: `GET /api/directory`, `/api/directory/sources`, `/api/directory/:id`,
  `POST /api/directory/:id/claim`, and operator routes under
  `/api/admin/directory/claims`.
- The operations console gained an "Imported profile claims" review queue.
