# v0.0.57 -> v0.0.58

End-to-end testing of the blood request flow found that its central safety rule
was not actually running. This release fixes that.

## "One call at a time" now works

The rule is that a requester must say how a call went before another donor's
number opens. Two separate faults meant it never fired in practice:

- **A cached datastore handle was serving stale reads.** A LanceDB table object
  is pinned to the version it was opened at, and these handles are kept for the
  life of the process. A reveal written a moment earlier was therefore invisible
  to the next query and only appeared after a restart - so the server always
  believed there was no unreported call. Reads now move the handle to the latest
  committed version first. This affected every on-demand table, including
  directory lookups after a claim.
- **A one-minute grace period defeated the rule for anyone clicking quickly.**
  It existed so the prompt would not appear while the caller was still on the
  call page, but it also let a requester open a screenful of numbers inside the
  window without answering for any of them. Removed. Reopening the *same* donor
  still reuses the open reveal, which is what returning to a call page needs.

A regression test pins the first fault, because it fails silently: everything
looks correct and simply does nothing.

## Smaller fixes

- The call page was titled "Imported donor archive". It now has its own title.
  It was already `noindex`, which is what matters for a page showing a contact
  number, but a page holding someone's phone number should not be mislabelled.
- `README.md` still said imported numbers are masked for everyone without
  qualification. Browsing still never reveals a number; the reveal flow is the
  documented exception, and the README now says so.

## Verified

Checked against a populated development datastore: search returns registered
members ahead of attributed public listings with the exact blood group first and
every number masked; publishing, revealing, blocking, reporting, and reopening
behave as specified; invalid outcome combinations are refused; the public
request feed exposes no patient or contact fields; an A+ donor does not see an
O- patient's request; and the directory renders without horizontal overflow at
375px.
