# v0.0.30 → v0.0.31

Pre-launch security hardening.

## Security

- Passwords are now bcrypt-hashed; legacy plaintext records are re-hashed on
  the next successful login. Minimum password length raised to 8 characters.
- API responses no longer include the `password` field or the session token.
- Sessions moved from localStorage bearer tokens to an httpOnly,
  `SameSite=Lax` cookie (`Secure` in production); TTL reduced 30 → 7 days.
- Removed the fake OTP flow (hardcoded `123456` fallback, `dev_otp` responses,
  `send-otp`/`verify-otp` endpoints). Registration is now a single step and
  accounts start unverified until a real SMS provider exists.
- `GET /api/requests/:id` no longer exposes contact details or donor phone
  numbers to unauthenticated callers.
- Added rate limiting: 10/15min on login and register, 300/15min on `/api`.
- Added `helmet` security headers with a production CSP.
- Anonymous fingerprints must be ≥16 characters, and ownership reassignment on
  login/register requires the body fingerprint to match the request header.

## Dependencies

- Added `bcryptjs`, `cookie-parser`, `helmet`, `express-rate-limit`.
- `npm audit` now reports 0 vulnerabilities (was 8) after safe updates,
  including a `tsx` bump for its bundled esbuild.

## Frontend

- Registration UI collapsed from a 3-step OTP flow to a single form.
- All API calls rely on the session cookie; token plumbing removed.
- Request detail page shows a "log in to see contact details" prompt for
  anonymous visitors.
