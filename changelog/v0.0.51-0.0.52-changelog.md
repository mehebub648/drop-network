# v0.0.51 -> v0.0.52

Groundwork for searching donors by upazila instead of by district. Nothing in
the user-facing flow changes yet.

## Upazila reference data

Requesters think in upazilas, not districts, but the project had no upazila
list. The scraped Bangladesh Scouts register does: 141,379 rows covering 621
upazilas across all 64 districts.

- New `scripts/generate-upazilas.ts` (`npm run generate-upazilas`) turns that
  register into a committed `server/upazilas.ts`.
- It lives in `server/` because the production image ships only `server/` and
  `dist/`; `src/lib/upazilas.ts` re-exports it to the browser so the data exists
  once.
- Stored spellings are kept byte-identical, because they are the join key for
  every imported listing. Display names are a separate field.
- 35 entries the register wrote in Bengali script now have reviewed English
  labels. Barguna and Jhalokati have no Latin spellings at all in the source, so
  without this their dropdowns would have been unreadable.
- Four places the register spells two ways (Chawk Bazar, Dakshin Keraniganj,
  Benapole Port, Barishal's airport thana) are merged into one entry that still
  matches rows stored under either spelling, so no listing is lost.

## Searchable upazila column

- `imported_donors` gains a filterable `upazila` column. The values were always
  in the stored document, so an existing datastore is migrated in place by the
  same schema-evolution and batched backfill path that added `public_id` - no
  re-import is needed.
- **First boot after upgrading rewrites every imported row** and takes a while.
  `/ready` reports 503 until it finishes.
- The backfill now remembers which rows it has rewritten. Some sources publish
  no upazila, and those rows would otherwise have been re-selected forever.

## Call report storage

- New `common_call_reports` table for revealed contacts and reported call
  outcomes. It is queried on demand and never loaded into the boot cache: a
  single search can list fifty donors and each one is expected to produce an
  outcome, so this table would hit the 10,000-row cache ceiling long before any
  other.

## Donor profiles

- Donor profiles can now record an upazila, plus an optional age and weight.
- Age and weight are self-declared and do not affect eligibility. Treating them
  as a screen would imply a medical assessment this project does not perform.
- Changing district clears a stale upazila rather than carrying it across.
- Without an upazila a donor will not appear in the upcoming upazila search, and
  the profile form says so.

## Documentation

- `docs/ARCHITECTURE.md` was stuck at `0.0.50` while every other version
  reference said `0.0.51`. Fixed, along with the new storage and reference-data
