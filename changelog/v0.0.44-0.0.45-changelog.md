# v0.0.44 → v0.0.45

## Datastore moved out of Docker volumes onto the host

The LanceDB datastore was inside named Docker volumes, which made it awkward to
back up, inspect, or copy, and meant the 130k imported donors were only visible
to whichever service happened to own that volume. It is now a bind-mounted
directory:

| Service | Host directory | Container path |
| --- | --- | --- |
| `app` (production) | `./data/lancedb` | `/data/lancedb` |
| `app-dev` (development) | `./data/lancedb-dev` | `/data/lancedb` |

`./data/scraped` already held the scraped NDJSON, so all runtime data now lives
under a single `./data/` directory.

- Existing volume contents were **copied, not moved** — `drop_drop_lancedb`,
  `drop_drop_lancedb_dev`, and the stale `drop_drop_lancedb_prod` are all still
  intact if anything needs to be recovered from them.
- `drop_node_modules` stays a named volume; it has to, so it does not shadow the
  host `node_modules`.
- `docker compose down -v` no longer destroys the datastore.
- `.gitignore` now ignores all of `data/` rather than just `data/scraped/`,
  because the datastore holds personal data.

Deployment docs gained a backup recipe for both Ubuntu and Windows.
